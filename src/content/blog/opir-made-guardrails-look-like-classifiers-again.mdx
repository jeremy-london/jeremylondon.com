[Opir](https://github.com/Knowledgator/Opir) is a reminder that much guardrail work is classifier-shaped.

Is the prompt a jailbreak? Is the response in a policy category? Should the request be allowed, blocked, redacted, routed, or reviewed? A judge model with a long explanation is not the only possible tool.

The request path can stay explicit:

~~~text
prompt or response
  -> safety classifier
  -> label scores
  -> policy decision
  -> allow, block, route, redact, or review
~~~

Labels matter because "unsafe" is too blunt. Harassment, malware, prompt injection, self-harm, and benign discussion of a risky topic need different product actions.

False positives are part of the product cost. A classifier that blocks security education or research content may protect one boundary while damaging another. Hard negatives keep the taxonomy and threshold honest.

A small classifier can sit before an expensive model or beside a local tool path. It does not eliminate judgment. It gives the system labels, thresholds, and a place in the request path where policy can act.

Safety becomes more manageable when it is treated as inspectable classification rather than magic text.
